# PassVault Database Design & Schema

## 1. Storage Philosophy & Privacy Principles

The database follows strict zero-knowledge constraints:
- **No plaintext credentials:** No columns exist for vault passwords, usernames, website URLs, or sensitive notes.
- **No recovery keys or AES keys:** The 25-character vault recovery key and derived encryption keys are strictly client-side secrets and are never stored in the database.
- **Argon2id for Authentication:** Account passwords use salted Argon2id hashes with 64 MB memory cost and 3 iterations.
- **Hashed Session Tokens:** Active session tokens stored in the database are hashed with SHA-256 to prevent compromise in the event of an unauthorized database dump.

## 2. Prisma Schema Models

### User (`users`)
- `id`: UUID (Primary Key)
- `email`: String (Unique)
- `passwordHash`: String (Argon2id format)
- `role`: String (`USER` | `ADMIN`)
- `isVerified`: Boolean
- `isSuspended`: Boolean
- `createdAt`, `updatedAt`: Timestamps

### AuthenticationSession (`authentication_sessions`)
- `id`: UUID (Primary Key)
- `userId`: Foreign key to `users`
- `sessionTokenHash`: SHA-256 hash of random 256-bit cookie token
- `ipAddress`: String
- `userAgent`: String
- `expiresAt`: Timestamp (7-day maximum age)
- `isRevoked`: Boolean
- `lastActiveAt`: Timestamp (tracks user activity for timeouts)

### MfaConfig (`mfa_configs`)
- `id`: UUID (Primary Key)
- `userId`: Foreign key to `users` (Unique)
- `isEnabled`: Boolean
- `secret`: Base32 TOTP Secret
- `backupCodes`: JSON array of single-use emergency backup recovery codes

### EncryptedVaultItem (`encrypted_vault_items`)
- `id`: UUID (Primary Key)
- `userId`: Foreign key to `users`
- `itemId`: UUID generated by browser client
- `encryptedPayload`: Serialized versioned JSON envelope (`version`, `algorithm`, `iv`, `salt`, `ciphertext`, `tagLength`)
- `revision`: Integer (incremented on each client update)
- `isDeleted`: Boolean (tombstone for cloud deletion propagation)
- `clientUpdatedAt`: Client timestamp

### AuditEvent (`audit_events`)
- `id`: UUID (Primary Key)
- `userId`: Foreign key to `users` (Nullable)
- `actorEmail`: String
- `eventType`: String (e.g. `AUTH_LOGIN_SUCCESS`, `VAULT_SYNC_PUSH`)
- `status`: String (`SUCCESS` | `FAILURE`)
- `ipAddress`, `userAgent`: Operational metadata
- `detailsJson`: Non-sensitive metadata (secrets are scrubbed)

## 3. Switching to PostgreSQL for Production

To switch to PostgreSQL in production:
1. Update `prisma/schema.prisma`:
   ```prisma
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```
2. Set `DATABASE_URL` in `.env`:
   ```env
   DATABASE_URL="postgresql://user:password@localhost:5432/passvault?schema=public"
   ```
3. Run `pnpm db:push` or `prisma migrate deploy`.
